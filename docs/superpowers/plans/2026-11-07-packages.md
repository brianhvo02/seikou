# Packages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut Seikou into seven npm workspace packages under `packages/` (bdmv, nas, pg, ass, engine, titles, fansubs) that another repository can import by name, with Seikou's own app, server and rendezvous importing them the same way and every existing check still green.

**Architecture:** Packages ship TypeScript source through `package.json` `exports`; no build step. Leaves move first (bdmv, nas, pg, ass), then the BD-J provider seam is cut inside `src/engine` while nothing moves, then the engine moves, then the server's titles and fansubs cores. Two behaviour seams exist: `PgRenderer` takes a `displayFlag()` instead of a register file, and `Player` takes an optional `BdjProvider` instead of importing `bdj/` statically. A smoke script proves consumption from outside the repo through `file:` links.

**Tech Stack:** npm workspaces, TypeScript 5 (`moduleResolution: bundler`, `verbatimModuleSyntax`), Vite 7 / Vitest 3, esbuild (server bundle), tsx, the existing golden-trace harnesses.

**Spec:** `docs/superpowers/specs/2026-11-07-packages-design.md` (and, for why, `~/encoding-tools/docs/superpowers/specs/2026-11-07-subtitle-helper-design.md`).

## Global Constraints

- Every package: `packages/<name>/package.json` with `"name": "@seikou/<name>"`, `"version": "0.1.0"`, `"type": "module"`, `"license": "LGPL-2.1-or-later"`, `"exports": { ".": "./src/index.ts", "./*": "./src/*.ts" }` plus one exact entry per asset (for example `"./default-font.ttf": "./src/default-font.ttf"`), `"files": ["src", "LICENSE", "NOTICE"]`; a `LICENSE` identical to the repo's; a `NOTICE` listing the ported files it holds with their upstream and copyright, moved out of `src/engine/NOTICE`.
- Imports between packages and from the app use the package name (`@seikou/bdmv/mpls-parser`, `@seikou/engine`); no package contains `../../src` or `../../server` imports. Imports inside a package stay relative.
- No behaviour change beyond the spec's seams. Golden traces (`tests/vm-trace/golden`, `tests/bdj/golden`, `tests/ass-trace/golden`) do not change.
- After every task: `npm run typecheck`, `npm test` (unit project), `npm run build`, `npm run server:build` all pass. Tasks that move engine files also run `npm run vm-trace`, `npm run bdj-trace` and `npm run ass-trace` replays (no Docker needed) and `npm run test:e2e -- --project chromium` once.
- SPDX and licence headers on moved files stay as they are; new files in packages carry `SPDX-License-Identifier: LGPL-2.1-or-later` in the header comment like their neighbours.
- `tests/helpers/*` that only package tests use move into that package's `test/` directory; helpers with users elsewhere stay and import the package.
- Commits: one per task, conventional subjects (`refactor(packages): ...`), with the moved paths done by `git mv` so history follows.
- Work on a branch from `main` (`main` and `beta` are at the same commit, 3dfb83a).

## Review Focus

1. **A BD-J disc opened by an engine built without the provider** (the package's own worker entry): the title picker appears with a notice naming `BD-J runtime`, playback of the chosen playlist works, and no `bdj/` code is in that worker's bundle. → Task 6 `opens a BD-J disc to the picker without a provider`; Task 7 `the package worker bundle contains no bdj module`.
2. **Assets reached through packages in the production build**: `audio.wasm`, `default-font.ttf` and the three jars appear in `dist/assets` and are precached by the service worker; the app plays a synthetic disc with ASS subtitles from `dist/`. → Task 7 build check and the chromium E2E run.
3. **The server bundle after titles and fansubs move**: `server/dist/server.mjs` starts, serves `/api/health` (or the existing liveness route), and `7zz.wasm` sits beside it. → Tasks 8 and 9 `server starts from the bundle`.
4. **The fansub line-up with the injected decoder** gives the same alignment as before for the fixture in `server/src/fansubs/__fixtures__`. → Task 9 `align through the ffmpeg decoder matches the fixture alignment`.
5. **A consumer outside the repo**: a temporary project with `file:` dependencies resolves `@seikou/bdmv`, `@seikou/ass` and `@seikou/engine` with tsx and Vite, with no `../` escape from any package. → Task 10 `scripts/package-smoke.sh`.
