# web/: the subtitle helper page

The page the user works in to choose fansub subtitles for a disc's episodes before an encode. `seikou-encode serve` serves it from `encoder/web/dist` together with its API (`encoder/src/server/README.md`), on 127.0.0.1, at `/helper/<session id>` with a token per run in the address (`?t=`); the page works on that helper session's disc, playlist and episode list. It is one column under a step bar: pick a release, match episodes, line up, with a Details panel for the names and languages the encode writes and "Save for encoding", which stores the record the encode reads.

## Concepts

- **State.** `HelperState` (`helper-model.ts`) holds everything the user chose: the AniList show and episode offset, the pool of releases (`releases`: each `PooledRelease` is the backend's answer, with its match at the offset, and where it came from, in the order they were added), each episode's file and tracks from any pooled release (or `none`), each episode's timing (alignment found, the user's nudge, accepted or not) and the metadata draft. `reduce` is pure; every change but moving between steps marks the state dirty. Episodes are keyed by their 1-based index in the session's episode list.
- **The pool.** `addRelease` adds a release at the end of the pool, and every episode that has no file yet (not one marked `none`) takes this release's matched file with all its tracks; episodes that have one keep it. Adding a release whose key is already pooled replaces it in place: an episode keeps its file while the file still fits it (one of its candidates in the new match, or an extra no episode is numbered for, before or after), else it loses its file, timing and drafted tracks and takes the release's matched file as above. That is how an offset change works: the page sets the offset, fetches every pooled release again at it, adds each answer back in pool order and sends `fillFromPool`, which gives every episode still without a file the first matched file in pool order (a re-add falls back only to its own release, so the order alone would decide). `removeRelease` clears the file, timing and drafted tracks of the episodes that used the release. A different show removes the SeaDex releases the same way and keeps Anime Tosho and own-file releases. `releaseOf`, `episodeFile` and `candidatesFor` (per release in pool order: the episode's matched files, then the release's files no episode is numbered for) read the pool.
- **Steps.** Step 1 is always open, step 2 once the pool holds a release, step 3 once an episode has a choice: a chosen file, from a pooled release, with tracks, or "No subtitles" (`canEnter`). An action that closes the step on screen (removing the last release, say) moves the page back to the furthest open one.
- **Browser history.** `useStepHistory` (`step-history.ts`) gives each step change the user asks for (Back, Next and the step bar, noted through the function it returns, which `App` calls for every `goTo` it dispatches) a history entry `{ step }`; the first load, and a step change the state forced (removing the last release, say), replace the current entry instead, so Back never lands on a step that can no longer be shown. The browser's Back and Forward move between steps. A `popstate` enters the stored step when `canEnter` allows it, else the nearest earlier step that does, and pushes nothing. The address never changes (`/helper/<id>` and `?t=` stay, so a reload works). A reload starts the page at step 1 (the saved record comes back there), with the entries the earlier steps made still behind it: after a reload on step 3, Back goes to the entries for steps 2 and 1 made before it. The step bar underlines the name of a step you can enter on hover and focus, and marks the one you are on in bold with a lit rail.
- **Tracks.** File ids are unique only within a release (Anime Tosho ids are numbers, own files are names) and track ids only within a file, so an episode's choice names its release's key, its file's id and its track ids, and every lookup keys on release and file together. Across releases a track is identified by its cached path (`CachedTrack.path`), which is also what the saved record names; the metadata draft keys tracks by it.
- **Metadata draft.** `MetadataDraft` (`metadata/metadata-model.ts`) holds per episode the record's metadata fields plus the subtitle tracks' order, names, languages and ticks, and the set of field paths the user edited. `defaultMetadata` fills the defaults: title `<Show> - <nn> - <episode title>` (`nn` and the AniList title are for the release's episode number: the session's index plus the episode offset), unnamed `und` video, audio named after its stream-table language (`jpn` is `Japanese`), subtitles named `<group> full` or `<group> signs` after the group of the release that episode's file comes from, chapters `Chapter n`. The defaults follow the state: whenever the show, the release, the chosen tracks or AniList's episode titles change, the page builds them again (`metadataDefaults`) and the `fillDefaults` action merges them into every field the user has not edited (`mergeDefaults`); an edit goes through `withUserEdit`, which marks its field (`episodes.<n>.title`, `video`, `audio`, `chapters` or `tracks`) so later defaults leave it alone. Filling defaults does not make the state dirty. A new show drops the old show's episode titles. An episode with no file (a restored episode whose release is gone) keeps the tracks its draft has; every action that takes a file away from an episode clears them. `toRecord` writes a language that is not three letters as `und`.
- **Details.** One episode at a time: the MKV title, the video's name and language, the audio streams and subtitle tracks (names, three-letter languages with the language's name beside, a tick to include, and their order: drag the grip, press the arrow buttons, or Alt+Arrow keys anywhere in a row), and chapter titles. The first ticked track of each list is marked Default; list order is the MKV track order.
- **Save and restore.** `SaveBar` asks for the saved record once the session is known and, when there is one, for each of its releases again (`release`), and restores the record with the releases that came back (`fromRecord`) unless the user has already changed something. `fromRecord` marks as edited only the metadata fields that differ from the defaults it would have proposed, so a restored record still takes AniList's episode titles; an episode whose release did not come back, or whose saved tracks are not in its release, has nothing chosen, so step 2 asks again. When a release or some of its cached files are gone (`missing`, matched to the record's releases by id, so two releases with one label stay apart), the bar lists each such release with its own "Fetch <release> again" (Anime Tosho releases), which fetches it, adds it to the pool and restores the saved file, tracks, timing and drafted tracks of the episodes that use it (`restoreRelease`), leaving the other releases, the other episodes and the user's edits as they are; the user's own files must be added again in step 1. A record from an older backend with a single `release` is read as one with that release (`currentForm`). While a release the saved episodes use is missing and not back in the pool, Save is off, so the saved tracks are not overwritten. An unreadable record file is reported, and saving replaces it. A record saved for another episode list of the same playlist is not restored (the backend answers it as none, naming that list); the bar then says "Subtitle choices are saved for episodes <spec>; saving here replaces them", and only while that line shows does Save ask the backend to replace it (`saveRecord(record, true)`). A save the backend refuses because such a record appeared meanwhile (`other-episode-spec`) saves nothing and shows the line, so the next Save replaces it.
- **The record.** `toRecord` writes the state as the backend's `SubtitleRecord`: `releases` lists, in pool order, only the releases some saved track comes from (empty when none), each track names its release's key in `release`, and `fonts` is the fonts of those releases, each once. Timing is written as an offset in `shiftMs`, a split as `split` with `shiftMs` 0, anything else as 0 and null, and an episode with no AniList title is named `Episode n`, n being the same number as in its MKV title (index plus offset). `fromRecord(record, releases, disc)` restores it from the answers for the record's releases, asked for again, in the record's order; without them the show, timings and metadata come back but no choices. It also reads a record in the older single-release form (`SingleReleaseRecord`), though the backend answers every record in the current form. The record keeps no alignment confidence, and an episode saved with no shift, split or nudge is lined up again.
- **Wire types.** `api-types.ts` declares every answer shape itself, because `encoder/src` and `@seikou/fansubs` need Node. Only types from `@seikou/nas/nas-api` (such as `FansubAlignment`) are imported.
- **Session.** `main.tsx` reads the helper session's id from the path (`helperSessionId`, `/helper/<id>`); every route the page calls is under `/api/sessions/<id>`, except the disc's files (`/api/discs/<key>/...`), which the engine reads. Without a session id in the path the page only says to open the address `serve` printed.
- **Token.** Read from `?t=` by `main.tsx` and kept only in the `HelperApi` object; requests send it as `Authorization: Bearer`, and URLs the page or the engine fetch directly (subtitles, fonts, disc files) carry it as `?t=`.
- **The engine.** Step 3 plays the disc in `@seikou/engine`, read from the backend's NAS-compatible disc API exactly as Seikou reads a NAS disc (`HelperApi.remoteDisc` gives the `RemoteDiscSpec`: an absolute base, the token and the manifest). There is one controller per page (`useController`), made when step 3 first shows; `showAt` opens the disc at a playlist time the first time (direct playback, no disc menus) and seeks after that. Browsers start audio only from a user action, so the player starts the engine's audio on the first press.
- **Line-up and preview.** One timing per episode: the backend lines up the episode's track with the most dialogue and answers `trackId`, and the found shift (or split) and the user's nudge apply to every track of the episode. The preview fetches the chosen track already retimed by the backend (`subtitleUrl` with the alignment; the release's own timing for `none` or `original`), so it is byte for byte what the encode muxes, loads it with the release's fonts as `File`s (`loadSubtitleFiles`), places it at the episode's start (`setSubtitleStart(0, startUs)`, which makes its cue times episode-relative) and, on a new episode, goes to the first dialogue line. The nudge is only ever the engine file's offset: whenever the engine reports the file at another offset (a fresh load, a key press), the step sets it from the difference with `shiftSubtitleFile`. One track shows at a time, with a switch when the episode has several.

## API

- `createApi(base, token, sessionId, fetch?)` in `api.ts`: one method per route of the session (`session`, `episodes`, `searchTitles`, `episodeTitles`, `seadex`, `searchTosho`, `fetchRelease`, `upload`, `release`, `align`, `subtitleUrl`, `fontUrl`, `record`, `saveRecord`). Failures reject with `ApiError { status, code, message, details }`; `status` 0 with `code: 'network'` means the backend did not answer. `helperSessionId(pathname)` reads the session id from `/helper/<id>`.
- `helper-model.ts`: `HelperState`, `PooledRelease`, `EpisodeChoice`, `HelperAction`, `initialState`, `reduce`, `canEnter`, `releaseOf`, `episodeFile`, `candidatesFor`, `metadataDefaults`, `toRecord`, `fromRecord(record, releases?, disc?)`.
- `metadata/metadata-model.ts`: `MetadataDraft`, `defaultMetadata`, `languageCode`, `languageName`, `defaultTrackName`, `defaultTitle`, `defaultTrack`, `move`, `withUserEdit`, `mergeDefaults`.
- `MetadataPanel({ state, dispatch, episodes, onClose })` in `metadata/`: the Details sheet.
- `SaveBar({ api, state, dispatch, session, episodes, children })`: the button row with Save for encoding (after `children`, such as Details), the status line, and the missing-release notice; it also restores the saved record on load.
- `episode-titles.ts`: `episodeTitlesOnce(api, alId)` and `useEpisodeTitles(api, alId)`, AniList's episode titles asked once per show and shared by the page and step 2.
- `MatchStep({ api, state, episodes, dispatch })` in `steps/`: step 2. One row per episode of the session (`episodes`, so an empty pool or a release missing an episode still lists every episode), numbered as the release numbers it (index plus offset; AniList title for that number from `episodeTitles`, else "Episode n"): a select of the files `candidatesFor` offers, one `optgroup` per release in pool order (a restored choice that is no candidate is added to its release's group; each option's value holds the release key and file id, `fileValue`), the file's tracks as checkboxes, "No subtitles"; "Not matched" lists, per release, the files no episode is numbered for and none uses. Back goes to step 1; Next opens step 3 once `canEnter` allows it, and a line under the buttons says why it is off until then. `match-model.ts` holds the pure file lists.
- `LineUpStep({ api, state, dispatch, session, episodes, controller })` in `steps/`: step 3. Per episode: `align` (a spinner, then the result in words), the preview, the alignment strip, the nudge (`[` `]` 42 ms, `{` `}` 10 ms, and buttons; the keys work unless a text field has focus), the track switch, and "Accept, next episode", "Use original timing" (fetches the track at the release's timing, nudge kept) and "Skip" (no subtitles). Each episode lines up, previews and loads fonts from its own release and file (`episodeFile`); a line-up answer is kept per episode, release and file, so another file is lined up afresh and a file chosen again gets its answer back. "Previous episode" (off on the first) goes to the episode before in the list, whatever its state, with its timing and nudge as they were, and the preview goes back to it; "Back", left of the others, goes to step 2. Without VapourSynth (`toolsReady: false` or a `tools-missing` answer) it says so and previews at the release's own timing. `lineup-model.ts` holds the words, formats, key map and the next- and previous-episode rules (`nextEpisode`, `previousEpisode`).
- `player/use-controller.ts`: `useController()` (the page's controller), `showAt(controller, api, session, timeUs)` and `PlayerLike`, the part of `PlayerController` the page uses (tests pass a stand-in). `player/Player.tsx`: `Player({ controller, episode })`, the canvas, play and pause, a seek bar over the episode's range and its time.
- `strip/strip-geometry.ts`: `stripLanes(input)` (speech in the top lane where it is, dialogue lines in the bottom lane moved by `shiftAt(alignment, fromMs)` plus the nudge, clipped to the view and scaled to pixels). `strip/AlignmentStrip.tsx` draws it on a canvas, 15 s either side of the playhead.
- `App({ api })`: the page shell; `StepBar` the three steps.
- `ReleaseStep({ api, state, dispatch })` in `steps/`: step 1. AniList search (only on submit), the picked show, the episode offset, SeaDex releases for that show (asked only once a show is picked), an Anime Tosho search and the user's own files, each picked release added to the pool and listed under "Releases in use" (label, group, source, a summary, Remove); a release already pooled shows as Added and picking it again fetches it again. A new offset fetches every pooled release again: answers that arrive are added back, releases that fail are named in a notice beside the offset and keep their old match, an answer is applied only for releases still pooled and only while its offset is the one in force, and a pick fetched at a superseded offset is fetched again at the new one. Next opens step 2 once a release is pooled; when no pooled file matched an episode (own files with no episode number in their names, say), a line under it says to pick them on the Episodes step. `releaseSummary`, `sourceText`, `anyEpisodeHasFile` and `refetchNotice` in `release-model.ts` are its pure helpers.

## The app

`main.tsx` renders `app/AppRoot.tsx`, which picks the page from the address and puts it in `app/AppShell.tsx` (the app bar with Library, Queue and Settings, the section on screen marked with `aria-current`, and a `progress` slot under the bar that stays empty until something fills it). The helper above is one of its pages, at `/helper/<session>`.

- `app/router.ts`: `parseRoute(pathname, search)` and `routeHref(route, search)` are a pure pair over the routes `/` (Library), `/disc/<key>`, `/disc/<key>/<playlist>` (Episodes), `/helper/<session>`, `/settings`, `/test/<job>`, `/queue`, `/queue/new?disc=&playlist=&spec=[&noSubtitles=1]` (its own route kind, `queueNew`, so it is never read as a job named `new`) and `/queue/<job>`; anything else is `notFound`. `routeHref` keeps the run's `?t=` token from the search string it is given. `navigate(href)` pushes history and tells `useRoute()`, which also follows the browser's Back and Forward; `Link` is an anchor that navigates that way (a modified click opens the browser's way).
- `app/app-api.ts`: `createAppApi(base, token)`, one method per library route (`library`, `rescan`, `setRoots`, `playlists`), failing with the same `ApiError` as the helper's client.
- `app/LibraryPage.tsx`: the discs found under the library folders (name, path, playlist count, "Subtitle choices saved" when any playlist has a record), a filter box (every word must appear in the name or path), Rescan (the page asks again every second while a scan runs), and the folders as an editable list (only the saved folders are edited and sent; a `--root` folder shows as "From the command line, this run only", with no Remove). A disc key is listed once, with "Also at <path> (<root>)" for other folders holding a copy; with several folders the line under a disc starts with its folder's name (and is just that name when the disc sits directly in it). A failed poll while a scan runs shows the error and polling goes on. The document title is "Seikou encoder" (the disc's name on its page, "Subtitle helper" on the helper). With no folders it says "No library folders are set" and the folder field is the way forward; a folder the last scan could not read is named in an alert and marked in the list while its earlier discs stay listed.
- `app/DiscPage.tsx`: a disc's playlists longest first with length, clips and chapters, "Likely main" and the saved-choices mark, each with a link to Episodes. A disc the library does not hold (or the backend answers `disc-changed` for) says so and links back to the Library.
- Episodes, Settings, Queue, the queue dialog and test pages are placeholders inside the shell until their pages exist.

## Building and running

- `npm run encoder:web:build` writes `encoder/web/dist` (`vite build --config encoder/web/vite.config.ts`), which `serve` needs.
- `npm run encoder:web:dev` serves the page with hot reload. Start `serve` first and set `SEIKOU_ENCODE_API` to its address; the dev server sends `/api` there. Open the dev page at serve's `/helper/<id>` path with its token as `?t=`.
- Both serve with COOP/COEP, because Seikou's engine needs `SharedArrayBuffer`.
- Tests run in the root Vitest `encoder` project (`npx vitest run --project encoder encoder/web`); component tests pick jsdom with a `// @vitest-environment jsdom` comment. Type-checking is `tsconfig.encoder-web.json` (DOM, `vite/client`); the Vite config is checked by `tsconfig.node.json`.
- `npx playwright test -c playwright.encoder.config.ts` runs the page end to end in installed Chrome (`encoder/tests/e2e/helper.spec.ts`): it builds the page, starts `serve` on the speech disc with recorded answers, and picks two releases, gives episode 1 the second release's file, walks the three steps with Previous episode and the browser's Back and Forward, then Details, Save, a reload that restores both releases and a look at the record on disk.

## Look

Dark only. The alignment strip is the one memorable element: both lanes in the accent (speech solid, subtitle lines outlined over a faint fill), a tick each second, the playhead in ink; the nudge's value beside it is the only amber on the page. One typeface, Instrument Sans (its width axis condenses the disc's name and headings), tabular numerals for times and counts (`.num`). Colours are tokens on `:root` in `styles.css`: base `#0F1B2D`, panel `#17273D`, ink `#E9EFF7`, muted `#8FA1BC`, accent `#4D9BFF` for the chosen item and alignment marks, amber `#F0B45B` only for the nudge. Left aligned, 16 px side gutters, usable at 375 px. No uppercase labels; the step bar is the only numbered thing.

## Where to look

- `main.tsx`: the entry point, reading the token and the session id.
- `App.tsx`: the header, step bar, the metadata defaults, and the step on screen.

- `metadata/MetadataPanel.tsx`: the Details sheet.
- `episode-titles.ts`: the shared AniList episode titles.
- `StepBar.tsx`: the steps.
- `step-history.ts`: `useStepHistory`, the step on screen kept in the browser's history.
- `steps/ReleaseStep.tsx`, `steps/release-model.ts`: step 1 and its pure helpers.
- `steps/MatchStep.tsx`, `steps/match-model.ts`: step 2 and its pure helpers.
- `steps/LineUpStep.tsx`, `steps/lineup-model.ts`: step 3 and its pure helpers.
- `player/`: the engine's controller for the page and the preview player.
- `strip/`: the alignment strip and its geometry.

- `helper-model.ts`: state, reducer, record conversion.
- `metadata/metadata-model.ts`: the metadata draft, its defaults and the merge.
- `styles.css`: the look.
