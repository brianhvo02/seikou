# M4 Jobs UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `seikou-encode app` opens one local app: a library of discs, a disc's playlists, chapter grouping with a preview, the subtitle helper on the chosen episodes, settings profiles, a test encode, and a queue of encode jobs run one at a time in the backend with live progress on every page.

**Architecture:** The helper backend becomes the app's backend: an app context (data directory, roots, token, tools, sources) holds helper *sessions* (disc, playlist, episode list) created on demand, a disc library scanned from the roots, profiles, and a `JobRunner` that runs `encodeEpisodes` in-process one job at a time, persisting to `jobs.json` and streaming progress over server-sent events. The page becomes a small client-routed app (Library, Disc, Episodes, Settings, Test, Queue, and the existing helper under a session) built by the same Vite config.

**Tech Stack:** Node 24, TypeScript strict ESM, React, Vite, Vitest (`encoder` project; jsdom + `@testing-library`), Playwright. External processes only: `vspipe` + BestSource, `SvtAv1EncApp`, `opusenc`.

**Spec:** `encoder/docs/superpowers/specs/2026-11-08-jobs-ui-design.md` (binding; read §3, §5, §5.1 and §6 closely). Parents: `2026-11-06-encoding-tools-design.md`, `2026-11-07-subtitle-helper-design.md`.

## Scope

In: everything in the spec's goals and §5.1, including the progress line on every page.

Out: the spec's non-goals (player, delivery, parallel encodes, quality metrics, ISO discs, remote use, filtering).

Decisions this plan makes (the spec leaves them to the builder):
- **Page routes** (client-side, `history.pushState`; the server answers `index.html` for any non-API, non-asset path): `/` Library, `/disc/<key>` Disc, `/disc/<key>/<playlist>` Episodes, `/helper/<sessionId>` the helper, `/settings` Profiles, `/test/<jobId>` a test's results, `/queue` and `/queue/<jobId>`. The token stays in memory and in the `?t=` of the first load; internal links keep the search string.
- **API layout:** app-level routes under `/api/` (library, discs, playlists, sessions, profiles, jobs, outputs); a session's helper routes under `/api/sessions/<id>/…` with the same sub-paths the helper uses today (`episodes`, `titles/…`, `fansubs/…`, `uploads/…`, `releases/…`, `episodes/<n>/align`, `episodes/<n>/subtitle`, `record`); disc file routes stay `/api/discs/<key>/manifest|files/…` for any disc in the library or a session.
- **Sessions:** `POST /api/sessions { discKey, playlistId, episodeSpec }` → `{ id }` (16 hex, kept in memory for the server's life; creating one for the same triple returns the existing id); `serve` creates one at start and opens `/helper/<id>?t=…`.
- **Progress events:** `GET /api/jobs/events` (SSE): `event: jobs` with the full job list on connect and on every state change, `event: progress` with `{ jobId, episode, framesDone, frames, fps, etaSeconds }` at most once a second.
- **Encode API changes:** `encodeEpisodes` gains `signal?: AbortSignal`, `onlyEpisodes?: readonly number[]` (1-based indexes to encode, others skipped), and `EncodeEvent` gains `kind: 'progress'` with `framesDone`, `frames`; episodes are written to `<name>.mkv.partial` and renamed when complete; `onEvent` also reports `'packaged'` and `'package-failed'`.
- **Jobs and profiles files** as the spec's §6, written atomically (`replaceAtomically` from `@seikou/titles`).
- **Default profile settings:** `{ crf: 25, preset: 4, filmGrain: 4, extraSvtArgs: [], opusBitrate: null, pgs: true, web: false, namePattern: 'episode-{n}' }`; `--film-grain` moves from the fixed SVT list into the settings (default 4, same result).

## Review Focus

1. **A crash or restart mid-encode**: no `.mkv` that looks finished but isn't; the job shows interrupted; retry encodes only the unfinished episodes. Tests in Task 6 (`.partial` rename) and Task 8 (`restart marks running jobs interrupted and removes their partial files`).
2. **Two helper sessions at once** (two tabs, two discs): their records, line-ups and caches never cross. Test in Task 1 (`two sessions keep their own episodes and records`).
3. **Cancel while a tool is mid-write**: every child process stops, the partial file is removed, the next queued job starts. Test in Task 8.
4. **The subtitle record changing between a job's first run and its retry**: every episode re-encoded. Test in Task 8.
5. **Paths from the client** (an output folder, an output file link, a disc key): nothing is read or written outside the roots, the data directory and the job output folders. Tests in Tasks 2 and 8.

  - Output folders: any absolute folder the user picks (spec §5.1), created if missing; a relative path answers 400 `output-not-absolute`.
